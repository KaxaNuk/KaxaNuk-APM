# `attribution_analysis_parameters.xlsx` — every parameter

One **General** sheet, three columns: the parameter name in column A (**do not modify**), your value
in column B, the description in column C. Created by `kaxanuk.attribution_analysis init excel`,
regenerated by `update excel` — which backs the old file up as `*.1.xlsx`.

`yes` / `no` are case-insensitive. The format values (`csv`, `parquet`, `excel`) must be lowercase.

| Parameter | Example | What it is |
| --- | --- | --- |
| `input_directory` | `Input` | base folder the two weights directories are resolved against |
| `weights_portfolio_directory` | `Portfolios` | subfolder of `input_directory` holding the book's weights |
| `weights_benchmark_directory` | `Benchmark_Portfolios` | subfolder of `input_directory` holding the benchmark's weights |
| `benchmark_returns_directory` | `Benchmark_Portfolios` | subfolder of `input_directory` holding the benchmark's return file |
| `investable_assets_directory` | `Input/Data` | market-data folder, **used as given** — not joined onto `input_directory` |
| `factor_returns_by_factor_directory` | `Input/Factor_Models` | per-factor folder, **used as given** — not joined onto `input_directory` |
| `portfolio_file_name` | `my_portfolio` | the book's weight file; the extension is optional |
| `benchmark_file_name` | `my_benchmark_weights` | the benchmark's weight file |
| `benchmark_return_file_name` | `my_benchmark_returns` | the benchmark's daily returns, in the weight-file shape |
| `start_date` | `2015-01-06` | `YYYY-MM-DD`, or `auto` to take it from the data |
| `end_date` | `2025-08-01` | `YYYY-MM-DD`, or `auto` to take it from the data |
| `brinson_fachler_method` | `yes` | run Brinson-Fachler |
| `factor_model_method` | `yes` | run the factor model — **and gate the dashboard** |
| `user_column_date` | `m_date` | the date column in *your* market-data files |
| `user_column_price` | `m_close_split_adjusted` | the price column returns are computed from |
| `market_data_input_format` | `csv` | `csv` or `parquet` |
| `portfolio_input_format` | `csv` | `csv` or `excel` — **`excel` does not complete; see `api.md`** |
| `dashboard_port` | `8050` | 1–9999, read back through `ExcelConfigurator.get_dashboard_port()` |
| `parameters_format_version` | `0.1.0` | system use. Do not modify. If the package asks, run `update excel` |

## The two directory rules, restated

`investable_assets_directory` and `factor_returns_by_factor_directory` are paths in their own right.
The other four are names resolved under `input_directory`. That is why the shipped template writes
`Input/Data` and `Input/Factor_Models` in full while the weights directories are bare names — and
why moving `input_directory` moves the weights but leaves the market data and the factors where they
were.

## The pre-run checklist

From the data-formats page, and worth running as a check rather than reading as advice:

- A market-data file exists in the assets directory for **every** ticker in the portfolio weights.
- Portfolio and benchmark weight files are in place, decimals, **no nulls**.
- Factor files reference only tickers present in the portfolio; a column for a name never held
  raises `DataValidationError`.
- Nothing else lives in the factor directory. Every entry but `.gitkeep` is read as a factor CSV.
- All input date ranges overlap — the run aligns to the intersection, and an empty intersection
  yields no data rather than an error you can read.
- `user_column_date` and `user_column_price` match the actual headers of the market-data files.
- `parameters_format_version` matches the installed package.

## Building it in code instead

`Configuration` is a frozen dataclass with exactly the fields above minus `dashboard_port` and
`parameters_format_version` (both belong to the configurator, not the configuration). Constructing
it directly is the right form for a sweep, a notebook or a test — **a sweep that edits a workbook
between runs is a sweep nobody will reproduce.**

```python
configuration = Configuration(
    input_directory="Input",
    weights_portfolio_directory="Portfolios",
    weights_benchmark_directory="Benchmark_Portfolios",
    benchmark_returns_directory="Benchmark_Portfolios",
    investable_assets_directory="Input/Data",
    factor_returns_by_factor_directory="Input/Factor_Models",
    portfolio_file_name="portfolio_weights.csv",
    benchmark_file_name="benchmark_weights.csv",
    benchmark_return_file_name="benchmark_returns.csv",
    user_column_date="m_date",
    user_column_price="m_close_split_adjusted",
    market_data_input_format="csv",
    portfolio_input_format="csv",
    start_date="auto",
    end_date="auto",
    brinson_fachler_method=True,
    factor_model_method=True,
)
```

Invalid values raise `ConfigurationError` from `__post_init__`, so a bad sweep cell fails at
construction rather than halfway through a run.

## `Config/.env`

`services.env_loader.load_config_env()` reads it, and the generated entry script calls that for you.

```text
KNAA_API_KEY_KAXANUK=LIC-...
```

The licence is also read from `~/.kaxanuk_license` or from the exported environment variable.
A KN Research Process repository's `Config/.env.template` carries this alongside the Backtest
Engine's `KNBE_API_KEY_KAXANUK` and the data providers' keys. **Never print any of their values.**
