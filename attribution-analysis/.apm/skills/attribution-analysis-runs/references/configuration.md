# `attribution_analysis_parameters.xlsx` — every parameter

The documentation's *Configuration Reference* is the source:
`https://kaxanuk-attribution-analysis.readthedocs-hosted.com/en/latest/user_guide/end_user_manual/configuration.html`.
This file repeats the table for work offline, with what the page does not say.

One **General** sheet, three columns: the parameter name in column A (**do not modify**), your value
in column B, the description in column C. Created by `kaxanuk.attribution_analysis init excel`,
regenerated by `update excel`, which renames the old file `.1.xlsx`, then `.2.xlsx`, and so on.
`yes` / `no` are case-insensitive; the format values (`csv`, `parquet`, `excel`) must be lowercase.

| Parameter | Example | What it is |
| --- | --- | --- |
| `input_directory` | `Input` | the base the next **three** directories are joined onto |
| `weights_portfolio_directory` | `Portfolios` | under `input_directory`: the book's daily weights |
| `weights_benchmark_directory` | `Benchmark_Portfolios` | under `input_directory`: the benchmark's daily weights |
| `benchmark_returns_directory` | `Benchmark_Portfolios` | under `input_directory`: the benchmark's daily returns |
| `investable_assets_directory` | `Input/Data` | market data, **used as given** — not joined onto `input_directory` |
| `factor_returns_by_factor_directory` | `Input/Factor_Models` | one CSV per factor, **used as given** |
| `start_date` | `2015-01-06` | `YYYY-MM-DD`, or `auto` to take it from the data |
| `end_date` | `2025-08-01` | `YYYY-MM-DD`, or `auto` |
| `portfolio_file_name` | `my_portfolio` | the book's weight file; the extension is optional |
| `benchmark_file_name` | `my_benchmark_weights` | the benchmark's weight file |
| `benchmark_return_file_name` | `my_benchmark_returns` | the benchmark's daily returns, in the weight-file shape |
| `brinson_fachler_method` | `yes` | run Brinson-Fachler |
| `factor_model_method` | `yes` | run the factor model — **and gate the dashboard** |
| `user_column_date` | `m_date` | the date column in *your* market-data files |
| `user_column_price` | `m_close_split_adjusted` | the price column returns are computed from |
| `market_data_input_format` | `csv` | `csv` or `parquet` |
| `portfolio_input_format` | `csv` | `csv` or `excel` — **`excel` does not complete in 0.2.0** |
| `dashboard_port` | `8050` | 1–9999, read back through `ExcelConfigurator.get_dashboard_port()` |
| `parameters_format_version` | `0.1.0` | system use. Do not modify; if the package asks, run `update excel` |

**`ExcelConfigurator` exits the process on a configuration error** — it logs the error and calls
`sys.exit` — so a bad cell in a notebook arrives as `SystemExit`.

## The pre-run checklist

The documentation's *Data Formats* page carries a checklist. Run it as a check, not as advice, with
what 0.2.0 adds:

- A market-data file exists for **every** ticker in the portfolio weights — and for every benchmark
  constituent, listed in the portfolio file at zero weight (observed in the source: benchmark weight on
  a name the portfolio file omits drops out of Brinson-Fachler).
- No market-data file has a blank price in any row, and every date is `YYYY-MM-DD` or `YYYY/MM/DD`.
  One bad file aborts the whole load.
- Portfolio and benchmark weights are **daily** — 240 to 260 rows a year once they span a year — in
  place, decimals, **no nulls**.
- Every weight file's first header is `Ticker` or **`date_column`**, the benchmark returns file
  included. `date` is rejected, whatever the documentation says.
- Nothing but factor CSVs lives in the factor directory. Every entry but `.gitkeep` is read as one, and
  each file's name, up to its first dot, is the factor's name.
- A factor column for a name the book never held is skipped, not an error; a held name missing from a
  factor file lowers that factor's coverage. Read the coverage line.
- All input date ranges overlap. An empty intersection raises; a configured window that contains no
  weight date raises `DateRangeError` as soon as the weights load; an explicit `start_date` before a
  factor file's first date raises too.
- `user_column_date` and `user_column_price` match the market-data headers.
- `parameters_format_version` matches the installed package.

## Building it in code instead

`Configuration` is a frozen dataclass with exactly the fields above, minus `dashboard_port` and
`parameters_format_version`, which belong to the configurator. Constructing it directly is the right
form for a sweep, a notebook or a test — **a sweep that edits a workbook between runs is a sweep nobody
will reproduce** — and a bad value raises `ConfigurationError` at construction instead of ending the
process.

```python
configuration = Configuration(
    input_directory="Input",
    weights_portfolio_directory="Portfolios",
    weights_benchmark_directory="Benchmark_Portfolios",
    benchmark_returns_directory="Benchmark_Portfolios",
    investable_assets_directory="Input/Data",
    factor_returns_by_factor_directory="Input/Factor_Models",
    portfolio_file_name="portfolio_daily_weights.csv",
    benchmark_file_name="benchmark_daily_weights.csv",
    benchmark_return_file_name="benchmark_returns.csv",
    user_column_date="m_date",
    user_column_price="m_close_split_adjusted",
    market_data_input_format="csv",
    portfolio_input_format="csv",
    start_date="auto",
    end_date="auto",
    brinson_fachler_method=True,
    factor_model_method=True,
)
```

`start_date` and `end_date` also take a `datetime.date`.

## `Config/.env`

```text
KNAA_API_KEY_KAXANUK=LIC-...
```

The generated entry script loads it; in a notebook, `load_config_env()` from
`kaxanuk.attribution_analysis.services.env_loader` does, as *Running from Python* shows. The licence is
also read from `~/.kaxanuk_license` or from the exported variable. A KN Research Process repository's
`Config/.env.template` carries this beside the Backtest Engine's `KNBE_API_KEY_KAXANUK` and the data
providers' keys. **Never print any of their values.**
